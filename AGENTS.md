# Working in this repository

This is Ozgur's public Python + FDE practice repository. An agent here does two recurring jobs: assign the next day, and review a submitted day. Read `memory/` before doing either.

## Assign day N

1. Read `memory/days.json`, `memory/profile.json`, the latest `days/dayNN/REVIEW.md`, and `coach/references/first.json` for the course starting point. Run `python3 tools/sync.py` first so the profile is current.
2. Design one 30-minute assignment, one rung above the last reviewed day. The course order is: values and names, expressions, strings, booleans and conditionals, loops, collections, functions, errors and tests, then JSON, then APIs and agent tools. Do not jump ahead of the evidence.
3. Bring memory forward: include a fresh task for each topic whose review is due, and a new example for each open misconception. Never reuse an earlier question.
4. Create `days/dayNN/` with `README.md` (scenario, time box, mode, tasks, finish steps), `solution.py` (stubs that `raise NotImplementedError`, docstring as specification), `test_dayNN.py` (subclass `DayCase` from `days/harness.py`; do not use `subTest`, it hides the skip), and `NOTES.md`. Follow `days/day01/` for layout and tone.
5. Verify the tests against a reference solution kept outside the repository, and verify that the untouched stubs report only skips. Never commit a reference solution.
6. Append the day to `memory/days.json` with `status: "assigned"`, run `python3 tools/sync.py`, commit and push.

## Review day N

1. Run `python3 -m unittest discover -s days/dayNN -v`. Read `solution.py` and `NOTES.md` in full.
2. Write `days/dayNN/REVIEW.md`: score, what was sound, each gap with the line it shows up on, the golden answer for anything missed, the Part A predictions marked, and what the next day will pick up.
3. Score 0 to 3 for the whole day: 0 not attempted or mostly wrong, 1 partly working with real gaps, 2 sound with minor gaps, 3 complete and well explained. Record help exactly as reported in `NOTES.md` (`none`, `hint`, `scaffold`, `ai_assisted`, `solution_seen`). Work done with help is practice evidence and never an unaided pass.
4. Update the day in `memory/days.json`: `status: "reviewed"`, `completed` (ISO date), `minutes`, `assistance`, `score`, `misconceptions` (short, reusable sentences, since identical wording is counted across days and emails).
5. Run `python3 tools/sync.py`, commit and push.

## Rules

- Do not write or complete `solution.py` for him before a day is submitted. After review, improvements go in `REVIEW.md` as explanation, not as edits to his file.
- Never claim mastery or interview readiness. Report evidence, help used, remaining gaps and the next step.
- `memory/profile.json` and `memory/lessons/` are generated by `tools/sync.py`. Do not edit them by hand.
- `coach/references/context.json`, `question-bank.json`, `interview-sources.json` and `private-notes.md` are private and git-ignored. Never add them, quote them, or copy their content into tracked files.
- The coach is live on his Mac from `~/.codex/skills/python-fde-email-coach`. Changes under `coach/` reach it only through `coach/scripts/install.py`, and only after the tests pass. Read `coach/SKILL.md` before touching scheduling, mail or assessment code.
- Standard library only. Run `cd coach && python3 -m unittest discover -s tests` and `python3 -m unittest discover -s tests` before committing code.
- Commits are his alone: no `Co-Authored-By` trailer.
